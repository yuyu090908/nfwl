# NFWL 開発ロードマップ

設計書 v2.1 第20章をもとに、各フェーズを2週間前後のスプリントに分けて進める。数値は全体仕様書の初期値を使い、遊んで調整する。

| Phase | 目標 | 完成条件 | 主な技術 |
| --- | --- | --- | --- |
| **1. 3D Prototype** | 選手1人とボールを操作 | ドリブルしてゴールを決められる | UE5 C++ / Enhanced Input / Chaos物理 |
| 2. Offline 5v5 | CPU相手に5対5 | 20分のCPU戦を最後まで遊べる | Behavior Tree / State Tree / アニメーション |
| 3. Online Alpha | 2人でオンライン対戦 | 別PC同士で20分完走＋第三者が遅延付き観戦 | Dedicated Server / Replication / NestJS |
| 4. Division | ランクマッチ | 結果でDivisionが正しく変わる | Backend / PostgreSQL / Redis |
| 5. NFT Player | 選手の育成・所有 | テストネットでNFT発行・移転し所有権が同期 | Solidity ERC-721（テストネットのみ） |
| 6. Champions League | Division 0大会 | 32クラブ大会を最後まで実行 | スケジューラ / 大会ロジック |
| 7. Spectator | 多人数ライブ観戦 | CL相当の同時試合を安定配信 | 観戦リレー / HLS・WebRTC |
| 8. Points & Staking | 無償ポイントで予想機能 | 63試合分で二重精算ゼロ・台帳差分ゼロ | 台帳サービス / 状態機械 / ジョブキュー |
| 9. Public Beta | 外部検証 | 想定同接で安定稼働 | 負荷試験 / 運営ツール |
| 10. On-chain Token | 実価値トークン | 法務ゲートG2・G3通過が前提（DEFERRED） | ERC-20 / KYC |

## 守ること（設計書21章）

- 小さく作ってテストしてから次へ。実行していないテストを成功と書かない。
- 試合の判定はサーバー（権威側）だけで行う構造を Phase 1 から保つ。
- 試合サーバーのコードはステーキング情報を参照しない。
- 本番NFT・本番トークン・実価値ステーキングは、法務ゲートとオーナーの明示承認まで実装しない。
